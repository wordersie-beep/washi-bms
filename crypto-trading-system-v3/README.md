# QuantCryptoV3

Адаптивная мультистратегийная квантовая торговая система для криптовалют на
cTrader Algo / cTrader Cloud.

```
21 620 строк C#   ·   302 теста   ·   собирается в QuantCryptoV3.algo без предупреждений
```

## Что это

Не «торговый робот», а полный контур принятия решений: движок данных, признаки,
классификация режима рынка, ансамбль из восьми специализированных стратегий,
байесовская оценка вероятности с калибровкой, расчёт матожидания с реальными
издержками, портфельные лимиты с учётом корреляции, лестница риска, планировщик
выходов, исполнение со сверкой, память результатов и адаптация.

Приоритеты, в этом порядке и без исключений:

```
ВЫЖИВАНИЕ КАПИТАЛА → ПОЛОЖИТЕЛЬНОЕ МАТОЖИДАНИЕ → УСТОЙЧИВОСТЬ → ПРИБЫЛЬНОСТЬ → МАСШТАБИРОВАНИЕ
```

## Чего это не делает

Прямо, до того как вы потратите время:

* **Не обещает прибыли.** Ничего не гарантирует.
* **Не создаёт преимущества.** Архитектура нужна, чтобы не потерять капитал и чтобы
  **сделать отсутствие преимущества видимым**.
* **На настройках по умолчанию отклоняет более 99% сигналов.** Это заявленное
  свойство, закреплённое тестом, а не недоработка.
* Наиболее вероятный итог полной процедуры валидации — вывод, что устойчивого
  преимущества на доступных данных нет. Система спроектирована так, чтобы этот вывод
  был получен на бэктесте, а не на реальном счёте.

## Структура

```
crypto-trading-system-v3/
├── src/
│   ├── Quant.Core/                      вся логика, НОЛЬ зависимостей от cAlgo
│   │   ├── Primitives/  Numerics/  Indicators/
│   │   ├── Data/  Features/  Regime/  Strategies/
│   │   ├── Probability/  Ev/  Portfolio/  Risk/  Sizing/
│   │   ├── Decision/  Exits/  Execution/  Adaptation/
│   │   ├── Stats/  Journal/  State/  Config/
│   │   └── TradingEngine.cs             оркестратор
│   └── QuantCryptoV3/QuantCryptoV3/     cBot: адаптер платформы
├── tests/Quant.Core.Tests/              302 теста, работают без cTrader
└── docs/                                14 документов
```

`Quant.Core` не ссылается на `cAlgo.API` вообще. Поэтому весь торговый цикл —
включая исполнение, восстановление после рестарта и сверку с брокером — тестируется
без запуска платформы, а отсутствие Windows- и GUI-зависимостей проверяется
компилятором, а не внимательностью.

## Быстрый старт

```bash
# Тесты
cd crypto-trading-system-v3/tests/Quant.Core.Tests
dotnet test

# Сборка .algo для cTrader
cd ../../src/QuantCryptoV3/QuantCryptoV3
dotnet build -c Release
# → bin/Release/net6.0/QuantCryptoV3.algo
```

Загрузить `.algo` в cTrader → Algo → cBots. Подробности и проверки совместимости с
облаком — в [документе 12](docs/12-cloud-deployment.md).

**Первый запуск — только в режиме `Shadow`.**

## Ключевые архитектурные решения

**Заглядывание в будущее исключено структурно.** Индикаторы двигаются только на
закрытых барах; канал Дончиана продвигается предыдущим баром; свинги подтверждаются
после N закрытий справа; перцентили сравнивают значение с историей, в которую оно ещё
не попало.

**Мартингейл невозможен по построению.** Все девять адаптивных множителей сайзинга
ограничены единицей сверху, поэтому ни одно сочетание входов и ни один набор
параметров не может превысить базовый риск. Проверяется перебором 3000 комбинаций.

**Система торгует нижнюю доверительную границу преимущества.** Оценка вероятности
всегда приходит со своей неопределённостью; неопределённость распространяется в
матожидание; решение принимается по `EV − z·σ(EV)`. Преимущество, существующее только
внутри собственных доверительных интервалов, — не преимущество.

**Согласие коррелированных стратегий не считается подтверждением.** Пересечение
выявляется структурно по объявленным семействам признаков — с первого бара, не
дожидаясь накопления корреляций.

**Цель ограничена историческим MFE.** Цель 3R на установке, которая исторически доходит
до 1.4R, — не цель, а допущение.

**Базовая линия живёт в том же коде.** Тривиальное пересечение EMA прогоняется на тех
же данных с теми же издержками. Если полная система не обгоняет его вне выборки,
сложность не окупается и должна быть снята.

## Двадцать два дефекта, найденных тестами и ревью

Каждый прошёл бы ревью. Полный разбор — в [документе 05](docs/05-test-plan.md).

| Дефект | Последствие |
|---|---|
| ATR ранжировался в единицах цены | В растущем инструменте все риск-контроли навсегда на максимуме |
| Перцентиль при одинаковых значениях = 1.0 | При фиксированном спреде брокера система отклоняла **100%** сигналов |
| Канал Дончиана включал оцениваемый бар | Стратегия пробоя **не могла сработать никогда** |
| Лимит проскальзывания в пипсах | 8 пипсов = 8 центов на BTC → все ордера отклонялись |
| CUSUM сравнивался со средним, отслеживающим деградацию | Тревога выключалась, когда стратегия была хуже всего |
| Иерархия вероятностей считала одни сделки на каждом уровне | Пять побед читались как двадцать |
| Восстанавливающаяся стратегия взвешивалась по записи, её отключившей | Восстановление недостижимо |
| Риск разорения останавливал по допущению | Свежая система не могла сделать первую сделку |
| `HighVolatility` конкурировала с `TrendUp` в одном argmax | Ярлык режима решался порядком обхода словаря |
| Рекалибровка не исправляла смещение | Измеримое смещение отбрасывалось вместо исправления |
| Таймфрейм был зашит в M5 | На M1 бот молчал — параметра просто не было |
| Планировщик выхода брал самый широкий стоп, потом отвергал его | 56% всех отказов; после правки — 0% |
| Прогрев истории прогонял полный торговый цикл | Дневная точка отсчёта привязывалась к историческому дню |
| Счётчик удержания рос от баров ЧУЖИХ инструментов | Стоп по времени срабатывал в N раз раньше |
| Объём закрытия читался у брокера ПОСЛЕ закрытия | Полное закрытие сообщалось как нулевое → аварийная остановка по сверке |
| Направленный лимит складывал знаковый риск с модулем | На книге из шортов лимит не срабатывал никогда |
| Защита по марже отключалась при нулевой свободной марже | Ровно там, где она нужна |
| Сигнал оставался заблокирован после безобидного отказа | Или разблокировался после таймаута → дубль позиции |
| Условие перепроданности было асимметричным | Длинная сторона не проверяла осциллятор вообще |
| Виртуальное исполнение не платило комиссию | Теневой режим доказывал работу у брокера без комиссии |
| Неизвестные издержки считались нулевыми | Сделка без спецификации выглядела идеальной |
| Отключённая стратегия не накапливала теневых исходов | Отключение было необратимым |
| Закрытие могло быть учтено дважды | Одна сделка удваивала вес в статистике и в счётчике серии |
| Позиции, закрытые во время простоя, терялись | Перезапуск бесшумно стирал проигранные сделки |
| Бюджет риска доставался первому пришедшему сигналу | Очерёдность событий платформы решала за качество |

## Требования

* .NET 6 SDK (сборка бота), .NET 8 SDK (тесты)
* cTrader 4.x+ с cTrader Algo
* Пакет `cTrader.Automate` (подтягивается автоматически из NuGet)
* Счёт у брокера с крипто-CFD, тиковые исторические данные

## Предупреждение

Торговля криптовалютами с плечом связана с риском потери всего капитала. Эта система
не снижает рыночный риск — она управляет размером позиции и ограничивает убытки в
рамках заданных лимитов. Стоп-лосс не гарантирует цену исполнения: при гэпе убыток
может существенно превысить запланированный, и это принципиально неустранимо размером
позиции.

Используйте только те средства, потеря которых для вас приемлема.
