# Установка QuantCryptoV3 в cTrader

## Вариант 1 — быстрый: готовый `.algo`

1. cTrader → вкладка **Algo** → раздел **cBots**
2. Кнопка **⋮** (три точки вверху справа) → **Add cBot** / **Import**
3. Выбрать файл `QuantCryptoV3.algo`
4. Бот появится в списке cBots

Если cTrader откажется принимать готовый `.algo` (бывает при несовпадении версии
платформы) — используйте вариант 2, он работает всегда.

## Вариант 2 — надёжный: сборка из исходников

1. Распаковать `QuantCryptoV3-source.zip`
2. Скопировать папку **`QuantCryptoV3`** целиком в:

   ```
   Windows:  Documents\cAlgo\Sources\Robots\
   macOS:    ~/Documents/cAlgo/Sources/Robots/
   ```

   Должно получиться так:

   ```
   Robots\
   └── QuantCryptoV3\          ← ЭТА папка даёт имя .algo
       ├── Quant.Core\
       └── QuantCryptoV3\
           └── QuantCryptoV3.csproj
   ```

   **Вложенность обязательна.** SDK cTrader берёт имя `.algo` из имени
   РОДИТЕЛЬСКОГО каталога проекта. Если положить `QuantCryptoV3.csproj`
   на уровень выше, артефакт будет назван по чужой папке.

3. cTrader → **Algo** → **cBots** → бот появится в списке
4. Нажать **Build** (молоток). Первая сборка тянет пакет `cTrader.Automate`
   из NuGet — нужен интернет, занимает 10–30 секунд.

## Запуск

1. В списке cBots найти **QuantCryptoV3** → **Add instance**
2. Выбрать инструмент (например BTCUSD) и таймфрейм графика

   Таймфрейм графика **не** определяет сигнальный — тот задан в коде (M5).
   Графиком удобно поставить M5, чтобы видеть то же, что видит бот.

3. Выставить параметры (см. ниже)
4. **Play**

## Параметры для первого запуска

```
Режим работы                  = Shadow      ← обязательно
Подтверждаю реальную торговлю = false
Сигнальный таймфрейм          = M5
Контекстный таймфрейм         = H1
Эталонный символ              = BTCUSD
Доп. символы                  = (пусто)
Дашборд каждые N минут        = 60
Признак жизни каждые N минут  = 15
Подробный журнал отказов      = false
```

**Только `Shadow` при первом запуске.** В этом режиме бот принимает все решения,
ведёт виртуальные позиции с реальными издержками и пишет полную статистику, но
не отправляет ордера.

## Таймфрейм: что им управляет

Работу бота определяет параметр **«Сигнальный таймфрейм»**, а не таймфрейм графика.
График можно поставить любой — бот подписывается на нужные ряды сам.

Если поставить график M1 и ожидать, что бот начнёт торговать по минуткам, ничего не
произойдёт: он продолжит работать по значению параметра. Меняйте параметр.

| Сигнальный | Контекстный | Нужно истории |
|---|---|---|
| M1 | M15 | 3.3 ч + 15 ч |
| M1 | H1 | 3.3 ч + **60 ч** |
| M5 | H1 | 17 ч + 60 ч |
| M5 | H4 | 17 ч + **10 суток** |
| M15 | H4 | 50 ч + 10 суток |

Контекстный обязан быть медленнее сигнального, иначе бот откажется стартовать с
понятным сообщением. Чем он медленнее, тем дольше прогрев: требуется 60 его баров.

**Для M1 разумная связка — M1 + M15.** Контекст H1 на минутном сигнале означает
2.5 суток прогрева, и всё это время бот честно скажет `insufficient history`.

При старте бот печатает, сколько именно истории ему нужно:

```
Решения принимаются на закрытии M1, контекст — M15. Таймфрейм графика на это не влияет.
Для начала работы нужно 200 баров M1 (≈3.3 ч) и 60 баров M15 (≈15.0 ч).
```

## Как понять, работает ли он

Раз в 15 минут бот печатает **признак жизни** — одну строку, по которой сразу видно
его состояние. Это главный ответ на вопрос «он работает или завис».

Прогрев, истории пока не хватает:

```
[жив] 09:15:00Z | BTCUSD баров 43 — ПРОГРЕВ, нужно ещё 157 | риск Normal | позиций 0 | решений 0 (принято 0)
```

Работает, решения принимает, сделок нет:

```
[жив] 12:30:00Z | BTCUSD баров 1204 TrendUp(68%) | риск Normal | позиций 0 | решений 485 (принято 0) | чаще всего: LowRegimeConfidence 33 %
```

Работает, но новые позиции заблокированы:

```
[жив] 14:00:00Z | BTCUSD баров 1580 Chop(22%) | риск Halt [БЛОКИРОВКА: DailyLossLimit] | позиций 0 | решений 640 (принято 0)
```

Строки нет вообще дольше 15 минут — бот остановлен или упал, смотрите лог выше.

### Тишина между строками — это норма

На настройках по умолчанию система отклоняет более 99% сигналов. Отказы пишутся в
лог только при смене причины, чтобы он не заполнялся одинаковыми строками. Поэтому
между признаками жизни лог может быть пустым часами — это работающая система,
которая ждёт.

Чтобы увидеть каждое решение, поставьте `Подробный журнал отказов = true` на
несколько часов.

### На что смотреть в причинах отказа

```
чаще всего: LowRegimeConfidence 33 %     ← норма, картина распределена
чаще всего: SpreadTooWide 87 %           ← подозрительно
```

**Одна причина занимает больше 60% — дело, скорее всего, не в рынке, а в пороге,
не подходящем для вашего брокера или инструмента.** Именно так при разработке были
найдены три дефекта, включая тот, из-за которого система отклоняла 100% сигналов у
брокеров с фиксированным спредом.

Если увидите такую картину — пришлите строку, разберёмся.

## Прогрев

Боту нужна история, прежде чем он начнёт принимать решения:

```
200 баров на M5  (≈ 17 часов)
60 баров на H1   (≈ 2.5 суток)
```

При старте он прогоняет историю графика автоматически. Если её мало, в логе
будет честная причина `DataQuality: insufficient history`.

Чтобы история точно была — откройте график инструмента и прокрутите его назад
на несколько недель до запуска бота.

## Запуск в облаке (24/7)

1. Убедиться, что локально бот работает и пишет дашборд
2. Экземпляр → **Cloud** → **Start in Cloud**

Бот рассчитан на Cloud: `AccessRights.None`, никакой графики, никаких файлов,
никакой сети, одна сборка. Подробности — `docs/12-cloud-deployment.md`.

## Бэктест

1. Экземпляр → **Backtesting**
2. **Data mode = Tick data from server** ← обязательно

   На M5 барные данные скрывают порядок внутри бара, а именно он решает,
   что сработало первым — стоп или цель.

3. Выставить **реальные** комиссию и спред вашего брокера
4. Запустить

По остановке бот печатает полный статистический отчёт: матожидание,
концентрацию прибыли, MAE/MFE, ценность фильтров.

**Читать его нужно снизу вверх** — чистая прибыль наименее информативна и легче
всего подгоняется. Начинайте с числа сделок и концентрации прибыли.
Подробно — `docs/06-backtest-plan.md`.

## Прежде чем рисковать деньгами

Полный список ворот — `docs/13-live-checklist.md`. Коротко:

```
Бэктест → Walk-forward → Монте-Карло → Shadow → Paper → Demo → Бой
```

Каждый шаг — ворота, а не рекомендация. Провал означает возврат назад.

Система не обещает прибыли. Наиболее вероятный итог всей процедуры — вывод, что
устойчивого преимущества на доступных данных нет; она спроектирована так, чтобы
этот вывод был получен на бэктесте, а не на реальном счёте.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Бот не появился в списке | Неверная вложенность папок — см. вариант 2, шаг 2 |
| Ошибка сборки, не найден `cAlgo.API` | Нет интернета для NuGet при первой сборке |
| `КОНФИГУРАЦИЯ ОТКЛОНЕНА` в логе | Противоречивые параметры; причины перечислены в логе |
| `ОТКАЗ: выбран режим Demo, но счёт РЕАЛЬНЫЙ` | Защита сработала верно: для реального счёта нужен режим Live с явным подтверждением |
| `insufficient history` | Прокрутите график назад, чтобы загрузилась история |
| Бот не торгует | Нормально. Смотрите признак жизни: он покажет, прогрев это, блокировка или отказы |
| Бот «не работает на M1» | Таймфрейм графика ни на что не влияет. Поставьте параметр **Сигнальный таймфрейм = M1**, а контекстный — M15 |
| Признака жизни нет дольше 15 минут | Бот остановлен или упал — смотрите лог выше |
| Одна причина отказа > 60% | Порог не подходит вашему брокеру; пришлите строку признака жизни |
