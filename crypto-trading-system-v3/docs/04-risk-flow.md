# Поток риска

## Шесть последовательных сужений

Риск проходит шесть независимых слоёв, каждый из которых может только **уменьшить**
итоговый размер или запретить сделку. Ни один не может его увеличить.

```
     БАЗОВЫЙ РИСК НА СДЕЛКУ  (0.35% по умолчанию)
                  │
     ┌────────────▼────────────┐
  1  │ ПОСТУРА РИСКА           │  Normal 1.00 │ Caution 0.65
     │ RiskEngine              │  Defensive 0.35 │ Halt 0.00
     └────────────┬────────────┘
                  │
     ┌────────────▼────────────┐
  2  │ КАЧЕСТВО РЕЖИМА         │  × уверенность режима
     │ RegimeAssessment        │  × 0.5 если переход не подтверждён
     └────────────┬────────────┘
                  │
     ┌────────────▼────────────┐
  3  │ КАЧЕСТВО СИГНАЛА        │  × уверенность ансамбля
     │ EnsembleDecision        │  × запас преимущества над порогом
     │ ExpectedValueResult     │  × вес ведущей стратегии
     └────────────┬────────────┘
                  │
     ┌────────────▼────────────┐
  4  │ СОСТОЯНИЕ РЫНКА         │  × таргетирование волатильности
     │ PositionSizer           │  × штраф за корреляцию с книгой
     │                         │  × качество данных
     │                         │  × качество исполнения
     └────────────┬────────────┘
                  │
     ┌────────────▼────────────┐
  5  │ ЖЁСТКИЕ ПОТОЛКИ         │  min(результат, HardMaxRiskPerTrade)
     │                         │  min(результат, свободный бюджет портфеля)
     └────────────┬────────────┘
                  │
     ┌────────────▼────────────┐
  6  │ ОГРАНИЧЕНИЯ БРОКЕРА     │  округление объёма ВНИЗ
     │ SymbolSpec              │  проверка маржи (ступенчатое плечо)
     └────────────┬────────────┘
                  │
            ИТОГОВЫЙ ОБЪЁМ
```

### Стабильность в весе стратегии

Приоритет системы — СТАБИЛЬНОСТЬ выше ПРИБЫЛЬНОСТИ, и вес стратегии это отражает.
Две стратегии с ожиданием +0.1R — разные вещи, если одна даёт его ровно, а вторая
чередует +2.1R и −1.9R: вторая уводит счёт в просадку, из которой первая не выходила бы.

Штрафуется ТОЛЬКО нижний разброс, мерой в духе Сортино. Большие выигрыши — не риск, и
наказывать за них значило бы предпочитать стратегию, которая срезает прибыль, той,
которая её берёт.

Поправка на разброс применяется к НАГРАДЕ и не применяется к ШТРАФУ. Иначе она
превратилась бы в способ удержать вес у стратегии, которая просто теряет деньги
аккуратно.

### Корреляционный стресс вселенной

Штраф за корреляцию при выборе размера — большее из двух: корреляции инструмента с
книгой и общей корреляции вселенной, когда та превышает 0.80.

Измеренная корреляция описывает прошлое, а размер позиции выбирается под будущее. В
стрессе корреляции сходятся к единице: инструмент, выглядевший независимым по истории,
перестаёт им быть ровно тогда, когда независимость нужнее всего.

### Перевод риска в объём

Риск задан в ПРОЦЕНТАХ ОТ КАПИТАЛА, то есть в валюте счёта. Стоп задан В ЦЕНЕ
инструмента. Делить одно на другое напрямую можно только когда котируемая валюта
совпадает с валютой счёта.

```
объём = риск_в_валюте_счёта / (расстояние_до_стопа × стоимость_единицы_цены)

стоимость_единицы_цены = Symbol.PipValue / Symbol.PipSize      ← от платформы,
                                                                 уже в валюте счёта
```

Счёт в EUR и ETHUSD: стоп в 50 долларов — это примерно 46 евро. Без перевода позиция
оказалась бы больше задуманной на весь курс пары, и об этом не сказала бы ни одна
проверка: система работала бы, сделки открывались бы, числа выглядели бы разумно.

Тем же курсом переводятся: фактический риск в записи сделки, требуемая маржа перед
сравнением со свободной маржой счёта, портфельный риск и прибыль в симулируемых
режимах. Издержки в `CostModel` переводить не нужно — они выражены в цене и делятся
на расстояние до стопа, тоже в цене, поэтому валюта сокращается.

Если платформа не сообщила стоимость пункта, пересчёт идёт один к одному, и
`SymbolSpec.MoneyConversionIsAssumed` это признаёт.

**Ключевое свойство:** каждый множитель на шагах 1–4 лежит в диапазоне (0, 1].
Отсюда следует, что произведение не может превысить базовый риск ни при каком
сочетании входов. Это свойство проверяется тестом, который перебирает 2000
случайных комбинаций всех девяти множителей.

## Лестница постур риска

```
        ┌──────────┐
        │  NORMAL  │  множитель 1.00
        └────┬─────┘
             │  2 убытка подряд │ просадка ≥50% лимита │ аномалия >0.5
             │  риск разорения >50% порога │ период восстановления
             ▼
        ┌──────────┐
        │ CAUTION  │  множитель 0.65
        └────┬─────┘
             │  4 убытка подряд │ просадка ≥75% лимита │ аномалия >0.8
             │  дневной убыток ≥70% лимита │ качество исполнения ниже порога
             ▼
        ┌──────────┐
        │DEFENSIVE │  множитель 0.35
        └────┬─────┘
             │  6 убытков подряд │ любой лимит достигнут
             │  маржа у стоп-аута │ риск разорения выше порога (при выборке ≥30)
             │  расхождение при сверке
             ▼
        ┌──────────┐
        │   HALT   │  множитель 0.00 — новых позиций нет
        └──────────┘     (открытые продолжают сопровождаться)
```

### Асимметрия эскалации и смягчения

Ухудшение применяется **немедленно**: ждать, когда условия уже ухудшились, нечего.

Смягчение требует **двух** условий одновременно:

1. прошло минимум `MinMinutesInRiskState` (по умолчанию 30 минут);
2. капитал восстановил заметную часть того, что вызвало ухудшение.

И происходит **по одной ступени за раз**. Прыжок из Halt сразу в Normal выбросил бы
всю осторожность, которую промежуточные состояния выражают.

Без обоих условий система колеблется между Normal и Defensive на каждом тике вокруг
порога — худший из возможных режимов.

## Почему мартингейл невозможен

Не «запрещён», а невозможен, на трёх уровнях:

| Уровень | Механизм |
|---|---|
| Форма расчёта | Все адаптивные множители ≤ 1.0. Произведение ≤ базовый риск. |
| Лестница постур | Валидация конфигурации отвергает немонотонную лестницу множителей. |
| Серии побед | `MaxWinStreakRiskMultiplier` по умолчанию = 1.0; значение выше 1.5 отвергается валидацией как «агрессивное масштабирование в серию». |

Тест `RiskIsNeverIncreasedByALoss` прогоняет 20 последовательных убытков и после
каждого утверждает, что множитель риска не вырос.

Отдельно отмечу: анти-мартингейл (увеличение после побед) по умолчанию тоже
выключен. Наращивание в серию побед — это ставка на продолжение серии, которая
гарантирует, что самая крупная позиция будет открыта ровно тогда, когда серия
закончится.

## Ограничения портфеля

```
                    ┌─────────────────────────┐
                    │ ОБЩИЙ РИСК ≤ 2.0%       │
                    └───────────┬─────────────┘
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
  ┌───────────────┐   ┌──────────────────┐   ┌─────────────────┐
  │ НА СИМВОЛ     │   │ НА КЛАСТЕР       │   │ НАПРАВЛЕННЫЙ    │
  │ ≤ 0.75%       │   │ ≤ 1.0%           │   │ ≤ 1.25%         │
  └───────────────┘   └──────────────────┘   │ с поправкой на  │
                              ▲               │ корреляцию      │
                              │               └─────────────────┘
                   ┌──────────┴──────────┐              ▲
                   │ CorrelationEngine   │              │
                   │ кластеры по         │              │
                   │ одиночной связи     │   √(wᵀ·C·w) — единственная форма,
                   │ при |ρ| ≥ 0.70      │   в которой полностью коррелированные
                   └─────────────────────┘   позиции складываются линейно,
                                             а независимые — квадратично
```

Смысл поправки на корреляцию: четыре лонга по разным монетам во время
коррелированной распродажи — это одна позиция четырёхкратного размера. Счёт узнаёт
об этом в момент, когда меньше всего может себе это позволить. Кластеризация по
реализованной корреляции — то, что заставляет лимиты связывать реальную, а не
номинальную экспозицию.

**Риск по текущему стопу, а не по исходному.** Позиция с перенесённым в безубыток
стопом не несёт риска снижения, и списывать с портфеля риск, которого больше нет, —
такая же ошибка, как игнорировать существующий.

## Постепенность вместо обрывов

Помимо ступенчатой лестницы, каждый лимит уменьшает размер **плавно** по мере
приближения:

```
доля использованного лимита:  0%    25%    50%    75%   100%
множитель:                   1.00   0.85   0.70   0.55   0.40 → затем ступень
```

Система начинает подрезать размер задолго до того, как упрётся в лимит. Торговать
полным размером вплоть до мгновения полной остановки — значит принимать максимальный
риск в момент, когда статистика уже говорит, что что-то идёт не так.

## Риск разорения

```
             ┌──────────────────────────────┐
             │ RiskOfRuinEstimator          │
             │ Монте-Карло, 2000 путей      │
             │                              │
             │ Моделирует явно:             │
             │  • компаундирование          │
             │  • КЛАСТЕРИЗАЦИЮ УБЫТКОВ     │
             └──────────────┬───────────────┘
                            ▼
              выборка ≥ 30 сделок?
                  ┌─────────┴─────────┐
                 ДА                  НЕТ
                  │                   │
                  ▼                   ▼
          > порога → HALT     > порога → максимум CAUTION
```

Различие принципиальное. При пустой истории винрейт и payoff, подаваемые в
симулятор, — это **допущения**, а не данные. Останавливать торговлю на основании
допущения означает, что свежеразвёрнутая система никогда не сделает первую сделку:
ей нужны сделки, чтобы накопить статистику, которая оправдает торговлю. Этот
тупик был найден тестом и устранён.

Кластеризация убытков моделируется намеренно: допущение о независимости убытков —
самое оптимистичное в классической арифметике риска разорения и то, которое рынки
нарушают надёжнее всего.

## Аварийные остановки

| Условие | Реакция |
|---|---|
| Расхождение бота и брокера при сверке | `ForceHalt`, новых позиций нет |
| Позиции у брокера без сохранённого контекста при старте | `ForceHalt`, требуется вмешательство |
| Непригодный снимок счёта | `Halt` немедленно |
| Экстремальное событие на рынке | `Defensive` + период восстановления |
| Маржа близко к стоп-ауту | `Halt` |
| Режим Demo на РЕАЛЬНОМ счёте | отказ от запуска |

Торговать, не зная своих позиций, — худшее из возможных состояний, и оно сделано
громким, а не тихим.
