# Архитектура QuantCryptoV3

## Главный принцип

Система строится в следующем порядке приоритетов, и он не подлежит пересмотру:

```
ВЫЖИВАНИЕ КАПИТАЛА → ПОЛОЖИТЕЛЬНОЕ МАТОЖИДАНИЕ → УСТОЙЧИВОСТЬ → ПРИБЫЛЬНОСТЬ → МАСШТАБИРОВАНИЕ
```

Из этого следует несколько решений, которые в коде выглядят как ограничения, а на
самом деле являются целью:

* **«Не торговать» — полноценное решение.** На настройках по умолчанию система
  отклоняет более 99% рассмотренных сигналов. Это не недоработка: отдельный тест
  (`DefaultConfigurationIsExtremelySelective`) утверждает именно это свойство и
  сломается, если система станет сговорчивее.
* **Нет пути, который увеличивает риск после убытка.** Мартингейл невозможен не
  потому, что запрещён в документации, а потому, что все адаптивные множители
  сайзинга ограничены сверху единицей. Ни один набор параметров, до которого может
  дойти оптимизатор, не способен превысить базовый риск.
* **Система торгует нижнюю доверительную границу преимущества, а не точечную оценку.**
  Преимущество, существующее только внутри собственных доверительных интервалов, —
  это не преимущество.

## Разделение на два проекта

```
src/
  Quant.Core/                     вся логика, НОЛЬ зависимостей от cAlgo
  QuantCryptoV3/QuantCryptoV3/    cBot: адаптер платформы, ~870 строк
tests/
  Quant.Core.Tests/               381 тестов, работают без cTrader
```

`Quant.Core` не ссылается на `cAlgo.API` вообще. Это даёт три вещи:

1. Весь торговый цикл — включая исполнение, сопровождение позиций, восстановление
   после рестарта и сверку с брокером — тестируется без запуска платформы.
2. Отсутствие Windows- и GUI-зависимостей проверяется компилятором, а не
   внимательностью. Это требование cTrader Cloud, и нарушить его молча нельзя.
3. Один и тот же код исполняется в бэктесте, оптимизации, теневом режиме и в бою.

Бот подключает исходники ядра через `<Compile Include>`, а не через `ProjectReference`.
Это сознательно: итоговый `.algo` остаётся **одной сборкой** и не может сломаться в
облаке из-за неупакованной вспомогательной DLL.

## Почему именно такой порядок в `OnBarClosed`

```csharp
1. обновить данные и признаки
2. классифицировать режим
3. оценить риск
4. СОПРОВОДИТЬ ОТКРЫТЫЕ ПОЗИЦИИ      ← до рассмотрения новых
5. периодические задачи (сверка, адаптация)
6. рассмотреть новые входы
7. сохранить состояние
```

Пункт 4 стоит перед пунктом 6 не случайно. Если сначала открывать новое, решение
принимается на основании портфеля, который уже устарел: лимиты риска проверяются
против картины, в которой позиция, только что закрывшаяся по стопу, всё ещё
занимает бюджет.

## Модель времени и защита от заглядывания в будущее

Заглядывание в будущее исключено **структурно**, а не аккуратностью:

* `TimeframeSeries.OnBarClosed` — единственный способ продвинуть индикаторы, и он
  принимает только закрытый бар;
* канал Дончиана продвигается ПРЕДЫДУЩИМ баром, поэтому «закрытие выше канала» —
  утверждение о прошлом, а не о самом себе;
* свинги подтверждаются только после закрытия N баров справа;
* перцентили сравнивают текущее значение с историей, в которую оно ещё не попало.

Каждое из этих свойств закрыто тестом.

## Интерфейсы для расширения

Три интерфейса существуют для того, чтобы позже можно было подключить обученные
модели, **не трогая ничего ниже по течению** — и, что важнее, чтобы статистическая
реализация оставалась доступной как запасной вариант:

```csharp
IMarketRegimeModel        →  StatisticalRegimeModel
ISignalProbabilityModel   →  BayesianProbabilityModel
IBroker                   →  CTraderBroker | SimulatedBroker
```

Модельный слой, который нельзя выключить, — это не улучшение, а новая точка отказа.

## Что НЕ реализовано и почему

* **ML-модели.** Спецификация требует сначала построить статистический базис и
  добавлять ML только при доказанном улучшении out-of-sample. Интерфейсы готовы,
  экспорт признаков (`FeatureVector.ToNumericMap`) готов. Модель без доказательства
  превосходства — это сложность без выгоды.
* **Внешние источники событий.** В облаке они ненадёжны, а построенный вокруг них
  цикл превращает сбой провайдера в остановку торговли. Вместо этого
  `AnomalyDetector` замечает *последствия* событий: скорость цены, объём, спред,
  здоровье потока котировок.
* **Стакан (Market Depth).** Доступен не у всех брокеров; система спроектирована
  работать без него. Интеграция возможна как дополнительный сигнал.
