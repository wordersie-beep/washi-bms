# Поток данных

## Два входа в систему

```
┌─────────────┐                                  ┌──────────────────┐
│ Symbol.Tick │─── котировка ──────────────────▶ │ TradingEngine    │
│  (часто)    │                                  │   .OnTick()      │
└─────────────┘                                  └────────┬─────────┘
                                                          │ ДЁШЕВО:
                                                          │ • проверка котировки
                                                          │ • статистика спреда
                                                          │ • обновление MAE/MFE
                                                          │ НИКАКИХ решений
┌─────────────┐                                  ┌────────▼─────────┐
│Bars.BarOpened│── закрывшийся бар ────────────▶ │ TradingEngine    │
│ (редко)     │                                  │  .OnBarClosed()  │
└─────────────┘                                  └──────────────────┘
                                                          │ ВСЯ работа
```

Разделение обязательно (раздел 149): тиков тысячи, баров единицы. Всё, что делается
на каждом тике, должно быть дёшево, иначе робот не успевает в облаке.

## Путь кандидата на вход

```
StrategyContext (только чтение: ни ордеров, ни счёта, ни портфеля)
        │
        ▼
EnsembleVoter.Vote()
        │  • каждая стратегия голосует со знаковой уверенностью
        │  • веса от StrategyWeightEngine
        │  • нормализация + жёсткий потолок 40% на стратегию
        │  • СКИДКА ЗА КОРРЕЛЯЦИЮ: 3 согласных, читающих одно
        │    и то же → 1 эффективный голос
        │  • ШТРАФ ЗА РАЗНОГЛАСИЯ: решение 60/40 слабее единогласного
        ▼
TradeGate.CheckPreTrade()          ← дёшево, отсекает большинство
        │  качество данных → риск → сигнал → режим → уверенность
        │  → аномалии → спред → волатильность → FOMO → погоня
        │  → возраст сигнала → дубликат
        ▼
ExitPlanner.Build()                ← план выхода ДО входа
        │  кандидаты на стоп: ATR / структура / инвалидация / MAE-квантиль
        │  берётся САМЫЙ ЗАЩИЩЁННЫЙ, а не самый узкий
        │  проверка: 0.6..4.0 ATR, издержки ≤ 35% риска
        ▼
CostModel.Estimate()               ← спред + комиссия + проскальзывание
        ▼
BayesianProbabilityModel.Estimate()
        ▼
ExpectedValueEngine.Evaluate()
        │  цель ограничена историческим MFE
        │  EV = p·W − (1−p)·L − C
        │  решение по НИЖНЕЙ ГРАНИЦЕ: EV − z·σ(EV) ≥ требуемое
        ▼
TradeGate.CheckEconomics()
        ▼
PositionSizer.Compute()            ← 9 множителей, все ≤ 1.0
        ▼
TradeGate.CheckPortfolio()         ← лимиты символа, кластера, направления
        ▼
OpportunityRanker.Score()
        ▼
ExecutionEngine.Open()
        │  1. проверка идемпотентности
        │  2. ОТМЕТКА об исполнении  ← ДО отправки
        │  3. market-range ордер с относительным лимитом проскальзывания
        │  4. повтор только на повторяемых ошибках, ограниченно
        │  5. запись качества исполнения
        ▼
OpenPosition + ExitPlan  →  журнал + сохранение состояния
```

## Что НЕ течёт вниз

Намеренно отсутствующие связи, каждая из которых была бы источником ошибок:

* **Стратегии не видят счёт, портфель и открытые позиции.** Их задача — иметь мнение
  о направлении. Позволительность этого мнения решают слои, которые видят книгу целиком.
* **Слои не знают о вышележащих.** `ExitPlanner` не знает, кто его вызвал.
* **Ядро не знает о cAlgo.** Ни одного `using cAlgo` вне папки бота.
* **Виртуальные сделки не попадают в реальную статистику.** Только в теневые срезы.
