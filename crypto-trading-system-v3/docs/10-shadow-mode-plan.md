# План теневого и бумажного режимов

## Место в лестнице

```
Бэктест → Walk-forward → Монте-Карло → ТЕНЕВОЙ → БУМАЖНЫЙ → Демо → Бой
                                       ▲▲▲▲▲▲▲   ▲▲▲▲▲▲▲▲
```

Теневой режим — первый контакт с **живым** рынком. Всё предыдущее происходило на
исторических данных, которые уже известны целиком.

## Чем теневой режим отличается от бэктеста

Это не «бэктест в реальном времени». Он проверяет вещи, которые исторические данные
проверить не могут в принципе:

| Что проверяется | Почему бэктест не может |
|---|---|
| Реальные спреды в реальные моменты | Историческая запись спреда усреднена и неполна |
| Поведение потока котировок | Задержки, паузы, всплески не сохраняются в истории |
| Разрывы данных у живого фида | Бэктест видит заполненную историю |
| Работа 24/7 без утечек памяти | Бэктест прогоняется за минуты |
| Поведение на выходных | Реальные выходные, а не размеченные задним числом |
| Корректность восстановления после рестарта | Настоящий рестарт настоящего процесса |
| Устойчивость к обрывам связи | В бэктесте связи нет |

## Теневой режим (Shadow)

```
Mode = Shadow
```

Система делает **всё**, кроме отправки ордеров:

* принимает решения и записывает их в журнал;
* «открывает» виртуальные позиции по реальным bid/ask;
* платит смоделированный спред, комиссию и проскальзывание;
* сопровождает позиции, двигает стопы, берёт частичные;
* ведёт полную статистику.

Ключевое: **виртуальное исполнение не бесплатно**. Теневой режим, в котором сделки
исполняются идеально, доказывал бы только то, что стратегия работала бы в мире без
издержек.

Виртуальные сделки записываются **только в теневые срезы** `PerformanceStore` и не
попадают в реальную статистику — иначе решения адаптации опирались бы частично на
сделки, которые никогда не платили спред.

### Длительность

```
Минимум:  4 недели ИЛИ 100 решений (что дольше)
Желательно: 8 недель, чтобы захватить смену режима рынка
```

Четыре недели на настройках по умолчанию могут дать очень мало сделок — система
разборчива. Это нормально и само по себе информативно: если за месяц не набралось и
десяти сделок, вопрос не в преимуществе, а в том, достаточно ли их будет вообще.

### Что проверять ежедневно

```
☐ Дашборд печатается, значения осмысленны
☐ Журнал отказов: распределение причин выглядит разумно
☐ Нет причины, занимающей > 60% отказов
☐ Нет исключений в логе
☐ Качество данных не деградирует
☐ Число решений растёт (система «жива»)
```

**Доминирующая причина отказа — главный диагностический признак.** Если 80% отказов
идут по одной причине, скорее всего это не рынок, а неверно откалиброванный порог —
ровно так были найдены дефекты с перцентилем спреда и лимитом проскальзывания.

### Критерии прохождения

```
☐ Решений ≥ 100
☐ Сделок ≥ 30
☐ Матожидание виртуальных сделок > 0
☐ Матожидание без хвостовых прибылей > 0
☐ Концентрация прибыли (топ 5%) < 60%
☐ Ни одного необработанного исключения
☐ Качество данных приемлемо ≥ 95% времени
☐ Просадка в пределах распределения Монте-Карло
☐ Распределение причин отказа осмысленно
☐ Пережит хотя бы один рестарт с корректным восстановлением
```

При отрицательном матожидании в теневом режиме **дальше не идти** (раздел 142).

## Бумажный режим (Paper)

```
Mode = Paper
```

Добавляет к теневому моделирование того, что ордер может **не исполниться**:

* задержки исполнения;
* случайные отказы брокера;
* отклонение ордера при превышении лимита проскальзывания.

Цель — чтобы путь обработки отказа действительно исполнялся, а не оставался
непроверенным до первого реального сбоя.

### Что проверять дополнительно

```
☐ Отклонённый ордер не блокирует сигнал навсегда
☐ Повторы происходят только на повторяемых ошибках
☐ Число повторов ограничено
☐ Качество исполнения считается и влияет на размер
☐ Сверка с брокером проходит
☐ Расхождение вызывает остановку, а не тихое продолжение
```

### Длительность

```
Минимум: 2 недели ИЛИ 50 сделок
```

## Обязательный тест на рестарт

Провести **намеренно**, не дожидаясь случайного:

```
1. Дождаться открытых позиций
2. Записать: позиции, стопы, постуру риска, серию убытков, дневной старт капитала
3. Остановить бота
4. Запустить снова
5. Сверить восстановленное состояние с записанным
```

Что обязано восстановиться:

| Значение | Что произойдёт при потере |
|---|---|
| Позиции с контекстом | Сопровождение вслепую или игнорирование |
| Счётчик серии убытков | Полный размер сразу после четырёх убытков |
| Кулдаун | Немедленный вход после серии |
| Дневная точка отсчёта | Дневной лимит убытка молча обнуляется |
| Пик капитала | Просадка считается от нового, более низкого уровня |
| Идентификаторы исполненных сигналов | Повторное открытие той же сделки |
| Состояния стратегий | Отключённая стратегия снова торгует |

Отдельно проверить сценарий «позиции есть, состояния нет»: система обязана
**остановиться и сообщить**, а не догадываться.

## Тест на потерю связи

```
1. Дождаться открытых позиций
2. Прервать сеть на 5 минут
3. Восстановить
```

Ожидаемо: качество данных отвергает устаревшие котировки, новых позиций нет,
существующие не закрываются паникой, после восстановления сверка проходит.

Важно: плохие данные — причина **не добавлять** риск, а не причина сбрасывать
позиции. Закрытие по сбою фида превращает техническую проблему в реализованный убыток.

## Сравнение с бэктестом

По завершении теневого периода сравнить с бэктестом за тот же календарный отрезок:

```
Метрика              Бэктест   Теневой   Расхождение
Сделок                   ...       ...          ...
Матожидание              ...       ...          ...
Средний спред            ...       ...          ...
Распределение отказов    ...       ...          ...
```

Существенное расхождение означает, что бэктест описывает не тот рынок, который есть.
Наиболее частые причины: спред в истории занижен, тиковые данные неполны, реальные
разрывы данных отсутствуют в записи.

Само это сравнение — самый ценный результат теневого периода.
