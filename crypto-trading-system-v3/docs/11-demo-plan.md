# План демо-режима

## Место в лестнице

```
Бэктест → Walk-forward → Монте-Карло → Теневой → Бумажный → ДЕМО → Бой
                                                            ▲▲▲▲
```

Демо — первый режим, где ордера **действительно отправляются на биржу брокера**.
Виртуальные только деньги.

## Что проверяет демо, чего не проверяли предыдущие режимы

| Что | Почему раньше не проверялось |
|---|---|
| Реальное проскальзывание | До этого оно моделировалось |
| Реальные отказы брокера | Моделировались синтетически |
| Реальное поведение стопов у брокера | Симулятор исполнял их по своим правилам |
| Реальные частичные закрытия | Округление объёма у брокера |
| Реальная маржа и её расчёт | Оценивалась по формуле |
| Реальная сверка позиций | Сверялись с симулятором |
| Работа в облаке 24/7 | Локальные прогоны конечны |

## Настройка

```
Mode = Demo
```

Защита режима сработает автоматически:

```
Demo + демо-счёт    → работает
Demo + РЕАЛЬНЫЙ счёт → ОТКАЗ от запуска
Live + демо-счёт    → продолжает как Demo, предупреждает
```

Второй случай обрабатывается отказом намеренно: это ошибка, при которой человек
считает, что не рискует, а рискует.

### Параметры для демо

```
RiskPerTradePercent      = 0.35   как планируется в бою
HardMaxRiskPercent       = 1.00
MaxTotalOpenRiskPercent  = 2.00
DashboardIntervalMinutes = 60
VerboseJournal           = false  (true только при разборе проблемы)
```

Размер риска **такой же, как планируется в бою**. Демо с завышенным риском не
проверяет то, что нужно проверить: поведение системы при том размере, который будет
использоваться.

## Длительность

```
Минимум:    4 недели И 30 сделок
Желательно: 8 недель, включая смену режима рынка
```

Оба условия обязательны. Тридцать сделок за неделю не заменяют четырёх недель работы:
часть проверяемого (утечки, поведение на выходных, восстановление) зависит от
календарного времени, а не от числа сделок.

## Ежедневная проверка

```
☐ Бот работает, дашборд печатается
☐ Нет исключений
☐ Постура риска осмысленна
☐ Теплота портфеля в пределах бюджета
☐ Качество исполнения ≥ 0.7
☐ Сверка проходит
☐ Нет доминирующей причины отказа
```

## Еженедельная проверка

```
☐ Сравнить фактическое проскальзывание с моделью
☐ Сравнить фактический винрейт с заявленным (калибровка)
☐ Проверить, не отключились ли стратегии и почему
☐ Сравнить метрики с теневым периодом
☐ Проверить журнал ценности фильтров
```

### Главная еженедельная метрика: калибровка

```
Калибровка: n=N  ECE=X%  Brier=Y  качество Z%
```

```
ECE > 10%  →  система систематически ошибается в своих вероятностях
```

Это важнее, чем текущий P&L. Плохо откалиброванная модель опасна не потому, что
неточна, а потому что каждый слой ниже — матожидание, порог преимущества, размер
позиции — умножает её число и множит ошибку.

При высоком ECE система автоматически поднимает требуемое преимущество, но устойчиво
плохая калибровка — повод вернуться на шаг назад, а не продолжать.

### Вторая метрика: качество исполнения

```
Исполнение: качество X%, проскальзывание ×Y, медиана Z пипсов, отказы W%
```

```
Множитель проскальзывания > 2.0  →  модель издержек занижает реальность
```

Если реальное проскальзывание вдвое хуже модельного, все расчёты матожидания были
оптимистичны. Это повод пересмотреть `NormalSlippageSpreadFraction` и **перепроверить
бэктест** с новым значением, а не просто принять к сведению.

## Сравнение уровней

По завершении демо свести таблицу:

```
Метрика                 Бэктест   Теневой   Демо
Сделок                      ...       ...    ...
Матожидание, R              ...       ...    ...
Винрейт                     ...       ...    ...
Средний спред               ...       ...    ...
Проскальзывание             ...       ...    ...
Максимальная просадка       ...       ...    ...
Концентрация прибыли        ...       ...    ...
```

Ожидаемая картина — **постепенная деградация**:

```
Бэктест  >  Теневой  >  Демо
```

Это нормально: каждый следующий уровень добавляет реальных трений. Настораживает
обратное:

| Наблюдение | Что это значит |
|---|---|
| Демо лучше бэктеста | Бэктест не описывает этот рынок; совпадение или ошибка в бэктесте |
| Резкое падение теневой → демо | Проскальзывание и отказы сильно хуже модели |
| Резкое падение бэктест → теневой | Исторические данные не отражают реальные спреды |

## Критерии прохождения

```
☐ Сделок ≥ 30
☐ Работы ≥ 4 недель
☐ Матожидание > 0
☐ Матожидание без хвостовых прибылей > 0
☐ ECE калибровки < 10%
☐ Качество исполнения ≥ 0.7
☐ Множитель проскальзывания < 2.0
☐ Ни одного необработанного исключения
☐ Ни одного расхождения при сверке
☐ Просадка в пределах P95 Монте-Карло
☐ Пережит рестарт с корректным восстановлением
☐ Пережита смена режима рынка
☐ Деградация относительно теневого объяснима
```

## Обязательные тесты в демо

### Рестарт под нагрузкой

Остановить и запустить бота при **нескольких** открытых позициях. Проверить полное
восстановление контекста и продолжение сопровождения.

### Проверка сверки

Вручную закрыть одну позицию **в терминале**, минуя бота. Ожидаемо: при следующей
сверке обнаруживается расхождение, система останавливается и сообщает.

Это проверка того, что аварийная остановка действительно работает. Пропускать её —
значит узнать о её неработоспособности в момент реального расхождения.

### Проверка дневного лимита

Если естественным образом не случится, временно снизить `DailyLossLimitPercent` и
убедиться, что после достижения новых позиций нет, а существующие продолжают
сопровождаться.

## Переход к бою

Только при выполнении **всех** критериев. И даже тогда:

```
Начальный риск в бою = 25–50% от протестированного
```

Демо-исполнение всё ещё отличается от реального: у брокера другая очередь исполнения,
другая ликвидность, другой приоритет. Первые недели боя — продолжение проверки, а не
её конец.
