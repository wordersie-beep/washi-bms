# План Монте-Карло

## Зачем

Историческая максимальная просадка — это **одна реализация** из распределения.
Торговать предстоит в другой. Система, показавшая 8% просадки на истории, вполне может
иметь 20% в 95-м процентиле — и именно этот показатель, а не исторический, должен
определять допустимый размер позиции.

Монте-Карло отвечает на вопрос: **«что могло бы произойти при том же преимуществе, но
другом порядке сделок».**

## Реализация

`MonteCarloSimulator` в `Quant.Core.Stats`. Принимает список результатов реальных
сделок в R и возвращает распределение исходов.

```csharp
var simulator = new MonteCarloSimulator(paths: 5000, seed: 20260919);

MonteCarloResult result = simulator.Run(
    observedR: trades.Select(t => t.R).ToList(),
    tradesPerPath: 500,
    lossClustering: 0.20,
    severeDrawdownR: 15.0,
    slippagePerTradeR: 0.0);

Console.WriteLine(result.Render());
```

Детерминирован по сиду: рандомизированный тест, который нельзя воспроизвести, нельзя и
использовать для принятия решения.

## Кластеризация убытков

Ключевое отличие от наивной перестановки.

```
Простая перестановка:   W L W W L W L W W L W    ← серии разрушены
Реальность:             W W L L L L W W W L L    ← убытки идут группами
```

Простая случайная перестановка разрушает серии, а серии — главный источник глубоких
просадок. Симуляция без кластеризации **систематически недооценивает хвост**, то есть
ошибается в единственную сторону, которая имеет значение.

Параметр `lossClustering` — вероятность того, что после убытка следующая сделка тоже
будет выбрана из убыточных:

| Значение | Смысл |
|---|---|
| 0.00 | Независимость (оптимистично, нереалистично) |
| 0.20 | Умеренные серии — **базовый сценарий** |
| 0.35 | Выраженные серии — стресс-сценарий |

Прогонять **оба**: 0.20 и 0.35. Решение принимается по худшему.

## Сценарии

### Сценарий 1. Базовый

```
paths = 5000, tradesPerPath = как в выборке, lossClustering = 0.20
```

Отвечает: какое распределение просадок соответствует наблюдённому преимуществу.

### Сценарий 2. Кластеризация под стрессом

```
lossClustering = 0.35
```

Отвечает: что будет, если убытки идут гуще, чем в истории.

### Сценарий 3. Деградация издержек

```
slippagePerTradeR = 0.05 … 0.15
```

Вычитает фиксированную величину из каждой сделки. Отвечает: что будет, если
исполнение станет хуже, чем на истории. 0.10R на сделку — реалистичная деградация при
ухудшении ликвидности.

### Сценарий 4. Длинный горизонт

```
tradesPerPath = 1000 … 2000
```

Историческая выборка может быть короче, чем планируемый срок работы. Просадка растёт с
длиной пути, и решение о размере позиции должно учитывать горизонт эксплуатации, а не
длину бэктеста.

## Что читать в результате

```
Просадка (в R):
  P5    P25   медиана  P75   P95   худшая
```

| Показатель | Как использовать |
|---|---|
| **P95 просадки** | Главное число. Планируйте капитал под него, а не под историческую просадку |
| Медиана просадки | Типичный сценарий |
| Худшая просадка | Худшее из 5000 путей — не «невозможное», а просто редкое |
| P5 итога | Пессимистичный исход: если он катастрофичен, размер слишком велик |
| Вероятность убыточного пути | Доля путей, закончившихся в минусе |
| Вероятность тяжёлой просадки | Доля путей, где просадка превысила порог |

## Перевод просадки в размер позиции

```
Допустимая просадка капитала, %
──────────────────────────────── = максимальный риск на сделку, %
        P95 просадки в R
```

Пример: если готовы пережить 20% просадки, а P95 = 25R:

```
20% / 25 = 0.8% риска на сделку
```

Это **верхняя граница**. Значение по умолчанию (0.35%) намеренно ниже, потому что
оценка P95 сама имеет погрешность, а ошибка в этом направлении необратима.

## Критерии прохождения

```
☐ Вероятность убыточного пути < 25%
☐ P95 просадки в пределах допустимого при планируемом размере позиции
☐ P5 итога не катастрофичен (не ведёт к остановке по лимиту просадки)
☐ Вероятность тяжёлой просадки < 10%
☐ Сценарий с кластеризацией 0.35 всё ещё приемлем
☐ Сценарий с деградацией издержек 0.10R всё ещё положителен
☐ Риск разорения (RiskOfRuinEstimator) ниже настроенного порога
```

Сценарий с кластеризацией 0.35 — самый информативный. Система, проходящая только при
0.20, рассчитана на рынок, который ведёт себя лучше, чем обычно.

## Связь с риском разорения

`RiskOfRuinEstimator` решает смежную, но другую задачу: он симулирует
**компаундирующий** капитал (риск — доля текущего капитала) и спрашивает о вероятности
достичь порога разорения.

| | MonteCarloSimulator | RiskOfRuinEstimator |
|---|---|---|
| Единица | R | доля капитала |
| Компаундирование | нет | да |
| Вопрос | распределение просадок | вероятность разорения |
| Когда | при валидации | непрерывно в бою |

Оба моделируют кластеризацию убытков, и оба нужны.

## Чего Монте-Карло НЕ доказывает

**Перестановка сохраняет распределение результатов из выборки.** Если само
преимущество было иллюзией — например, следствием подгонки — Монте-Карло построит
красивое распределение вокруг несуществующего преимущества.

```
Монте-Карло проверяет, ВЫДЕРЖИТЕ ЛИ ВЫ путь при данном преимуществе.
Он не проверяет, СУЩЕСТВУЕТ ЛИ преимущество.
```

Существование преимущества устанавливается walk-forward анализом (документ 08) и
теневым режимом (документ 10). Монте-Карло применяется **после** них, а не вместо.
